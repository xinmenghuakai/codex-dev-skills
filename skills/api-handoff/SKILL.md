# API Handoff

接口事实只来自当前 Go 代码：路由、Controller、req/res、Service 返回和常量。项目未配置接口文档平台时默认生成一份 Markdown 接口文档；项目明确启用 YApi 时按项目配置生成 YApi 产物；ApiPost 仅在用户明确要求时处理。字段无法从代码确认时标记待补，禁止推测。

## 不适用的轻量行为修复

已有接口若仅调整查询筛选、排序、分页、结果覆盖范围或既有数值参数的有效范围，且 method/path、鉴权/中间件、请求/响应字段形状、状态码和业务错误码均不变，本 Skill 不因“客户端可看到返回内容不同”而自动触发。`feature-delivery` 的 `delivery_mode=targeted_fix` 遇到这类改动时，只有用户明确要求接口文档、YApi、ApiPost 或前端变更表，才调用本 Skill。

新增/删除路由，或请求/响应字段、鉴权/中间件、状态码/错误码、字段类型/空值语义发生变化时，仍属于接口交付范围，必须按本 Skill 从真实代码冻结契约；不得用上述例外规避文档或同步要求。

## 执行方式

先按项目配置和用户要求确定交付模式，再选执行方式。Agent、模型与档位读取 [模型分级与 Agent 路由](../feature-delivery/references/model-routing.md)。

新建事实提取 Agent 和 Executor 均默认显式使用 `fork_turns="none"`，遵循上述路由的“子 Agent 上下文”规则。向事实提取 Agent 交接当前接口范围与源码入口；向 Executor 交接冻结契约、生成/同步范围和授权，不用完整聊天历史代替契约。

### 小批 Markdown 连续交付

同时满足以下条件时，默认由当前主 Agent 连续完成，不再固定派事实提取 Agent 和 Executor：

- 本次完整范围为单仓、同一客户端、最多 3 个接口；不得拆分原本更大的接口任务以套用本路径。
- 项目模式已核验为 `delivery_mode=markdown`，且 `apipost_requested=false`、`frontend_change_table_requested=false`；只生成一份脱敏 Markdown，不涉及平台产物、同步或真实请求。
- 接口调用链和请求响应结构清晰，字段、必填、枚举和空值语义都能从当前代码确认，不涉及跨仓公共契约、复杂多态响应或未确认口径；当前模型能可靠完成事实提取。

主 Agent 使用当前会话模型，先从真实代码整理接口事实清单并核对源码基线、接口集合、字段依据和 `unresolved=[]`，再生成 Markdown 并逐项对照。此轻量路径可在当前会话内冻结清单，不要求临时 JSON 文件或双 Agent schema；目录、脱敏和产物核验要求仍适用。生成时发现缺项、漂移或冲突，先回到代码核对，不能猜字段。

条件在生成前或过程中失效时退出本路径：未解决字段或源码漂移先澄清、重新提取并冻结；需要双 Agent 时，由事实提取 Agent 核对当前代码并写入下述临时契约，再交 Executor，不能直接转交未经其核验的主 Agent 清单。最终回传实际执行者、产物路径、覆盖接口、核验与清理结果，不伪造两个 Agent 的执行记录。

### 双 Agent 交付

超出上述范围、需要 YApi/ApiPost/独立前端变更表，或用户明确要求分工时，保留两个职责，二者均不得派生子 Agent：

1. `api_handoff_agent` 读取真实 Go 代码并冻结接口契约，只负责“理解代码和确认事实”，不得写 YApi/ApiPost 或生成最终交付物。
2. `api_handoff_executor` 只消费冻结契约，生成、校验已声明的交付物，并在授权后同步和读回；不得重新解释业务代码或补猜字段。

无法选择自定义 Agent 时按路由表“直接调用回退”处理并如实说明当前模型，不得假装已切换。此路径不因接口数量少而跳过平台身份、写入授权和版本校验。

## 双 Agent 冻结契约交接

仅双 Agent 路径使用本节的临时 JSON 和 schema。事实提取阶段在 Git 工作区之外生成唯一临时文件 `<task_tmp_root>/scratch/api-handoff-contract-<任务标识>.json`，至少包含：`schema_version`、源码仓库/分支/客户端、目标接口清单、method/path/路由前缀/鉴权/中间件、Controller、绑定方式、req/res、必填与枚举依据、变更类型、源码位置、`delivery_mode=markdown|yapi`、`apipost_requested=true|false`、`frontend_change_table_requested=true|false`、`unresolved` 和契约摘要。禁止写入密码、Token、Cookie、真实手机号、证件、uid 或业务数据。

- `unresolved` 非空、源码版本漂移或接口集合不完整时不得交给 Executor。
- Executor 开始前校验契约文件存在、`schema_version` 支持、`unresolved=[]`、三个交付选择字段有效，并核对源码仓库/分支/基线未漂移；不满足时退回事实提取阶段。
- Executor 只按冻结的 `delivery_mode` 和两个 requested 标记生成产物：`markdown` 只生成 Markdown；`yapi` 才生成 YApi JSON；只有 `apipost_requested=true` 才生成 Swagger/处理 ApiPost；只有 `frontend_change_table_requested=true` 才生成独立前端变更表。缺字段、模式与项目配置冲突，或任务包要求默认生成未声明产物时停止，不得回读代码自行改口径。
- 成功、失败或取消后删除临时契约；对外只保留脱敏交付物和校验/读回证据。

## 交付物目录解析

生成任何文件前先确认源码仓库、任务标识和生效的全局/项目 `AGENTS.md`。主 Agent 在任务包中一次性声明绝对路径 `task_tmp_root`、`delivery_root`、`contract_path`，所有执行者复用，不按子阶段重复建立整套目录。

- 临时根：按生效的全局/项目目录约定确定仓外任务目录 `task_tmp_root`；没有约定时先确认位置。冻结契约、一次性脚本、生成 JSON、导入中间文件和定向编译缓存放 `scratch/`；脱敏校验、同步读回报告放 `evidence/`。
- 正式交付根：按项目或既有工作区约定确定 `delivery_root`，例如工作区的 `outputs/api-handoff/`；位置不明确时先确认。可直接交付的 Markdown、前端清单和用户明确要求保留的导入包按 `markdown/`、`frontend/`、`yapi/`、`apipost/` 分目录。相同任务复用已有工作区；长期维护并提交的技术文档仍按项目约定放 `doc/`。
- 用户本次明确指定其他位置时沿用该授权；项目或旧 Skill 的 `tmp/api-handoff`、系统临时目录和旧仓内生成目录只作历史兼容入口，不得据此覆盖上述已确认的目录规则。工具强制路径沿用工具约定。
- 新任务写入前确认执行环境可写目标目录。路径不足时说明实际权限限制，不静默退回系统临时目录或仓内，也不改聊天数据库或扩大权限。
- 不因更新规则搬动正在运行的任务。已冻结任务包继续按原来声明的真实绝对路径读取契约，不能只因旧路径前缀拒绝有效契约；新契约使用新规则。历史资料保持旧入口读写，必要时新入口反向链接到原实体；只有空闲且已验证新旧路径读写兼容时才迁移实体。
- 所有生成物默认不提交 Git；位于仓外时核对真实路径确实在仓外，位于用户明确指定的仓内目录时用 `git check-ignore` 和 `git status --short` 核对。敏感临时目录 `0700`、文件 `0600`，不再使用后删除本任务契约，保留必要脱敏证据。
- 交付时报告各类产物的绝对路径、仓外/忽略状态与平台同步状态。写入目录成功不代表平台同步成功。

## 交付模式选择

先读取项目生效的 `AGENTS.md` 或用户明确指定的项目配置，再选择唯一默认模式：

1. 项目明确配置 `YApi` 为启用状态，并给出可核验的项目标识与同步方式时，使用 YApi 模式；默认生成 YApi 产物，不再额外生成默认 Markdown。
2. 项目明确禁用 YApi，或没有任何接口文档平台配置时，使用 Markdown 模式；默认只生成一份 `.md` 接口交付文档，不生成 YApi JSON，也不申请 YApi 写入授权。
3. 仅发现 YApi 脚本、旧 JSON、文档链接、环境变量或历史映射，不能视为项目已配置 YApi；不得据此自动切换模式。
4. 用户要求在未配置 YApi 的项目中使用 YApi 时，先停止并请用户补充或确认项目级 YApi 配置，不得猜测地址、项目 ID、分类或凭据变量。
5. ApiPost 不参与默认模式选择；只有用户明确要求时才生成或同步，其授权边界保持独立。

项目配置只记录平台开关、非敏感项目标识、服务地址或地址来源、同步脚本以及凭据环境变量名；Token、Cookie、密码和其他凭据不得写入项目配置。事实提取 Agent 将上述判定固化为 `delivery_mode`；Executor 不得根据任务名称、旧产物或环境变量再次推断或升级交付模式。

## 圈定接口

- 参数是接口路径：逐个处理。
- 参数是版本/需求：先从 plan 确认仓库和目标分支；没有 plan 时用默认主分支的 merge-base diff 圈定 Controller、req/res，再反查路由。
- 无参数且无法从当前需求确认：询问要交付的接口。
- 用户要求同步到本机 ApiPost 时，默认只交付本次需求新增、修改，以及已有同步映射的删除项；不得扫描、迁移、覆盖或删除未映射的历史接口，除非用户明确要求全量迁移。

## 提取代码事实

对每个接口依次确认：

1. 从 `routes/`、`route/` 或真实路由目录得到完整前缀、method、鉴权/中间件和 Controller；客户端分类遵循生效的 `AGENTS.md`。
2. 从 Controller 得到绑定的 req、Service 调用和响应来源。
3. 按 json tag、类型和注释展开 req；必填性依次取 binding/validate tag、Controller 显式校验和 Service 的强制约束，Go 非指针类型本身不代表必填。无法确认时标记“必填性待补”并阻止最终交付。内嵌 `CommonReq`/`PreCommonReq` 只在分类说明中描述，不重复铺到接口字段。
4. 按真实绑定方式写请求：GET 或无 body 请求写入 `req_query`；form 请求写入 `req_body_form`；JSON 请求写入 `req_body_other`。form/JSON 必须带匹配的 `Content-Type`，不得根据 method 猜编码。
5. 按 Go 结构体顺序递归展开 res。枚举依次取字段注释、常量定义和 Service 事实；均不存在时标记“枚举值待补”并阻止最终交付。
6. 用目标分支 merge-base 区分接口新增和字段变更，分别标记当前版本新增/改/删。
7. 需要可直接联调的示例时，先读取相关 `*_test.go`、测试 helper 和已有请求样例；只把能由代码或测试确认的字段填入。测试未覆盖的必填字段必须从 Controller/Service 的真实校验补齐，不能凭字段名猜测。真实测试数据只可用于本次经授权的本机私有环境，不得进入任何仓内或共享交付物。

## 脱敏交付物

- YApi JSON、Swagger、前端变更表、导入日志和业务仓文件都是可共享交付物：只写字段事实、非敏感类型示例和变量模板；不得写入真实 uid、用户/订单标识、手机号、令牌、Cookie、密码、调试密钥或其他测试业务数据。
- 对身份或凭据字段，所有示例、默认值、枚举、扩展字段、嵌套数组/对象及请求/响应 JSON 一律使用 `{{变量名}}`；说明文字可以解释字段用途，但不得出现“敏感字段名 + 非变量实际值”的赋值内容。校验器必须递归阻断上述泄露，错误信息不得回显原值。
- “贴近真实类型”仅适用于非敏感字段；真实可请求参数只保存在本次经授权的本机私有环境，且不得回写到 YApi、ApiPost 导入文件、前端文档、仓库或对话日志。

## 默认 Markdown 接口文档

仅在 Markdown 模式执行。一个任务只生成一个文件，写入 `<交付物根>/markdown/<版本或任务标识>/<版本>_<主题>_接口交付.md`；项目另有明确命名规范时沿用项目规范。文件至少包含：

- 后端仓库、分支、基线、客户端、生成时间和接口事实来源；
- 本次新增、修改、删除的接口总表，包括标题、method、完整 path、鉴权/中间件和调用说明；
- 每个接口的请求位置、Content-Type、字段路径、类型、必填性、枚举、空值语义和非敏感示例；
- 真实响应外层、响应字段结构、错误或降级语义，以及前端需要调整的行为；
- 删除项、兼容性风险、仍待确认项和对应源码位置。

字段顺序与 Go 定义一致；敏感值只使用变量模板。项目启用 YApi 时默认不生成本文件，只有用户明确要求额外提供 Markdown 时才生成。

存在待确认事实时，主 Agent 可依据事实提取阶段已核验的内容和未解决清单整理 Markdown 草稿，顶部标记“未定稿”；源码漂移时先对新基线重新核验已知事实。草稿不交给 Executor，也不能作为正式接口交付证据或标记 `api_handoff_completed=true`，不得宣称已同步。它不跳过原接口范围对应的事实提取分工；最终交付仍须消除未解决项、重新冻结并通过 `unresolved=[]` 等生成前校验。

## YApi 与 ApiPost

仅当已选 `delivery_mode=yapi` 或用户明确要求 ApiPost 时，读取 [平台交付与同步](references/platform-sync.md)，再生成平台产物或执行已授权同步。Markdown 模式且未要求 ApiPost 时不加载本节引用。

平台地址、身份、格式、写入授权、版本冲突和逐项读回均遵守该协议；生成本地文件不代表同步成功。各类外部写入及真实请求授权相互独立，不得从生成文档的授权推导。

## 前端专项变更表

仅在用户明确要求独立的前端变更表时生成，写入 `<交付物根>/frontend/<版本或任务标识>/<版本>_<主题>.md`；只有用户明确要求长期沉淀，且项目 `AGENTS.md` 或文档约定允许时，才改写到项目的长期文档目录：

- 顶部记录后端仓库、YApi 分类和真实响应外层或外部协议；只写脱敏变量和非敏感示例。
- 主表列出接口、方法、路径、变更（新增/改/删）和调用说明。
- 字段明细只列变化字段及嵌套路径、类型、空值语义、枚举和前端行为；全量字段留在 YApi。
- 删除接口/字段必须显式提醒前端清理调用。

只有用户明确要求，或已授权的 `feature-delivery`/`release` 包含长期文档提交时，才提交项目长期文档；只暂存本次文档。一次性前端变更表保存在上述正式交付根，不提交业务仓 Git。

## 交付

按实际启用的模式列出 Markdown、YApi、ApiPost 和前端专项文档；未启用或未要求的产物不得列为已生成。另列出以下人工事项：

- YApi 模式下的平台导入及需手动删除的存量接口；
- ApiPost 脱敏 Swagger 2.0 文件、格式/能力与写入授权状态、YApi/ApiPost 映射与 pending operation 读回证据、私有环境手工配置、删除禁用状态与因副作用未自动验证的接口；
- 向团队发送接口变更通知；
- 仍待补的必填性、类型、注释或枚举（存在时不得标记最终完成）。
