# SQL 与 GORM 审查

正确性优先于“看起来更快”；通用经验只能作为调查信号。

## 模型与速度

用户直接调用 `$sql-check` 时读取 [模型分级与 Agent 路由](../feature-delivery/references/model-routing.md) 的“独立 SQL/GORM 专项审查”；由完整 Review 触发时继承已经按审查风险选出的 Reviewer，在同一阶段完成本 Skill，不再改派模型或 Agent。直接调用及无法选择对应 Agent 时遵守路由表“直接调用回退”；速度模式由 Codex 管理。

## 建立事实

1. 读取适用的 `AGENTS.md`、plan、完整需求 diff 和调用方，圈定 Raw/Exec、Where/Scopes、Join、Select/Group/Order、事务及间接 DAO。
2. 确认参数与权限来源、业务口径、分页和返回结构，并读取真实 Model、migration、连接配置和索引。
3. schema、表结构或数据量不明时明确限制，不猜测。只有具备只读能力且确有必要时才运行带真实库名前缀的 `EXPLAIN`。

## 检查

- **安全与范围**：动态值参数化；动态列/排序/表名使用白名单；校验用户、租户、组织和资源归属；敏感信息不进入日志；UPDATE、批量写入和任务扫描必须有可验证范围。
- **删除语义**：遵守项目逻辑删除约定。发现 `DELETE`、GORM `.Delete()` 或先删后插时核对模型；没有逻辑删除字段时不得建议硬删。
- **结果集**：有效数据过滤、LEFT JOIN 条件位置、一对多重复、NULL/零值/空切片、时间与时区、闭开区间、GROUP/DISTINCT/HAVING、排序分页及 Scan 类型。
- **事务并发**：全程使用同一 tx，错误正确回滚；唯一约束、锁、条件更新、影响行数和幂等能防重复写。
- **DDL 与迁移**：核对真实库名、表规模、数据库版本和线上 DDL 能力；检查 expand/contract 兼容顺序、锁表与元数据锁、磁盘和复制延迟、旧版本代码兼容、默认值/回填、重复执行与半执行恢复、回滚或前滚方案。大表 DDL、不可逆变更或无法证明在线执行边界时必须阻止发布并要求人工决策。
- **性能**：N+1、无界查询、深分页、循环加载、索引与过滤/排序/分组顺序、函数或隐式转换、左模糊、大表 JOIN、临时表、锁范围和事务时长。

`SELECT *`、子查询、`OR`、`NOT IN` 或三张以上 JOIN 不自动构成缺陷。索引建议必须对应真实查询并比较现有索引，说明等值、范围、排序与最左前缀；缺少数据分布或 `EXPLAIN` 时只标记待验证。没有仓库模式和执行计划证据时不建议 `FORCE INDEX`。

## 输出

按严重性分组，每项给出文件行号、实际 SQL/GORM 链、触发数据条件、正确性或性能影响、调用链/表结构/索引/EXPLAIN 证据及符合现有抽象的最小修复方向。区分已确认问题、待线上证据验证和可选优化。

默认只读；用户明确要求修复或 `feature-delivery` 已授权返回实现阶段时才实施。没有问题时说明通过并列出缺失的结构、执行计划或数据量证据。
