# 运行状态、上下文与收敛

长任务、用户追问进度、工具/Agent 中断、上下文压力或重复失败时读取本文件。

## 执行状态真实性

- 只有确有运行中的工具、命令或阶段 Agent，才能说“正在执行/实现/测试/发布”。准备任务包、等待授权或已结束的调用不算；无活动项时明确“当前没有后台任务在运行”。
- 汇报前读取真实状态，给出对象、`running/waiting/completed/failed/interrupted`、最新证据和下一关口。代码证据优先用实际文件、diff、命令输出或提交；无产物时明确“已启动，但当前还没有文件改动证据”。
- Agent 接收任务不证明界面 Working，也不证明已有代码。用户追问时重新检查活动 Agent、运行命令和工作区。
- 默认按共享工作区描述。只有已创建真实独立 worktree/目录时才能说隔离，并给绝对路径、同步方式和状态；不得称“隔离环境写完自动合并”。
- 新消息打断、工具异常或 Agent 中断后，枚举 Agent 状态并检查 Git 状态/diff，区分主任务与阶段 Agent。不得因主轮次结束说“没做”，也不得在无活动项时称会后台继续。
- 只有文件/外部状态读回、验证和 Gate 满足时才能报告完成；未改、部分、失败、阻塞或中断逐项说明证据和下一动作。

## 上下文压力

在关键阶段结束、需要交接或中断恢复时，按需要更新一份当前执行快照；已有记录仍准确时直接复用。出现口径遗忘或矛盾时，先用相关代码和记录核对再更新。不按工具调用次数、输出行数或主观速度推测上下文容量；上下文压缩交由 Codex 管理。

任务已授权维护 plan 时覆盖固定“当前执行快照”；只读阶段或无 plan 时只在结果和后续任务包携带，不擅自写文件。快照仅保留当前阶段/授权、有效口径、plan/仓库/分支/改动、验证、风险、人工事项和下一关口。后续只读快照、定向 plan 章节和实时仓库状态；不声称精确计算剩余 Token，也不替代自动压缩。

## 执行收敛

- 先用 `rg`、编译器、格式校验、schema/索引和定向测试筛选事实，再用模型解释分歧。
- 从源头限制输出：先限定仓库/路径、时间窗、标识、错误、测试名和字段，证据不足再扩大一层。
- 快照保留失败账本：动作/命令、错误指纹、已改变的输入/环境/方法、结果、下一条不同路径。同一错误指纹只有至少一项改变后才可重试。
- 已确认决策默认冻结；新证据推翻时，有 plan 先同步，无 plan 更新内联契约和快照。业务取舍变化重新确认。
- 达到授权阶段门槛后停止，不为“再保险”新增无依据 Review、Agent、全文回读或工具调用。
- Agent 或模型中断后，按任务包记录的 `task_difficulty`、`selected_agent`、`selected_model` 和真实产物恢复。范围或风险没有变化时不重复升级模型；发生变化时按模型路由重新分级，不得声称已自动切换。
